## Visual and interaction decisions

Warm neutral sidebar, white workspace, light borders, compact typography, quiet green selection, dark primary publishing buttons and platform marks. Navigation exposes real connected accounts and queue counts. Large promotional dashboard panels are replaced by a compact working header, inline counts and content controls.

The calendar has week/month views, previous/next/today controls and opens real immutable publication snapshots. Channel, text and status filters operate on the API data already loaded (up to 200 recent publications / 100 drafts per workspace). Mobile uses a vertical week agenda and a two-column month grid instead of shrinking a seven-column calendar until unreadable. Calendar creation opens a draft; the actual date is selected after approval, not silently scheduled by clicking an empty cell.

The editor retains separate provider variants, title/content validation, image upload, public image consent, canonical URL, DEV tags and UTM suggestions. The always-visible preview is a readable content simulation, not a provider-rendered guarantee. Saving does not bypass approval. Existing scheduled snapshots retain their approved text when the draft changes.

Dialogs lock background scrolling, trap keyboard focus, close with Escape and restore focus. Details retain API-confirmed versus user-reported publishing states, manual metrics, explicit cancellation/retry and ambiguous-result protection.

## Remaining work and acceptance plan

| Priority | Work | Acceptance condition |
| --- | --- | --- |
| P0 before customer handoff | Production pilot after deployment | Customer-owned LinkedIn and DEV connect, publish at the scheduled time, return working permalinks, and disconnected credentials stop unsent posts. |
| P0 | Operational monitoring | Alert/queue for failed publishing and support requests; named person handles failures and deletion requests. Current intake is persisted but has no email notification/admin inbox. |
| P0 | Recovery and account support | Verified password reset and email verification, documented restore procedure and access ownership. |
| P1 | Date-based pagination and direct links | Fetch selected date ranges beyond 200 recent publications; share/bookmark an authenticated channel, date, draft or publication without losing state on refresh. |
| P1 | Editing scheduled publications | Explicit server endpoint to replace/reschedule an approved snapshot with concurrency protection and audit history. No cosmetic drag-to-reschedule until this exists. |
| P1 | Recurring channel queue | Durable posting slots and IANA time zones, DST-safe recurrence, pause controls and daily-limit tests. Current scheduling is one publication at a time. |
| P1 | Composer convenience | Explicit copy-to-channel, reusable templates, media library and richer format support backed by each provider's API. No unsupported video/carousel/music controls. |
| P1 | Teams and client separation | Membership, invitations, roles, designated reviewers and audited approvals; existing workspaces are owner-scoped. |
| P2 | Additional automatic channels | Each requires provider access, OAuth/permissions, encrypted credential lifecycle, platform-specific content validation and live publishing tests. Medium/Reddit/Indie Hackers remain manual. Facebook Groups remains companion-based. |
| P2 | Analytics and SEO/GEO attribution | Collect permitted platform metrics and authorized website analytics; distinguish observed metrics from manual entries and do not equate publishing with indexing/ranking. |
| P2 | Billing and quotas | Payment/webhook handling, entitlements, cancellation and per-plan limits before advertising paid plans. |

The UI changes do not provide new network permissions, provider integrations or analytics automatically. Keep actual integration scope visible to customers.

## Run locally

Use the existing local setup and configuration. Run `npm run cloud:dev` and `npm run web:dev` in separate terminals; open the Vite URL. For isolated browser QA, run `npm run web:build` then `npm run test:marketing:ui`.

Deployment remains the existing main-branch GitHub Actions flow. No additional hosting project or deployment is created by the UI redesign.
